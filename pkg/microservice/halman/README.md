# halman 后端接入

已实现聊天基础，以及六个中文内置 Skill 的后端接入：工作流报错分析、服务报错分析、项目初始化、批量服务初始化、环境巡检、效能诊断。支持参数补问、待确认清单、模板版本校验、明确确认后的逐项执行和 Skill 根执行统计。普通聊天、参数补问、等待确认和结果待核实均不计为完成任务。

还提供重新回答、按回答版本反馈、管理员报告、历史物理清理、失败项重试清单及待核实结果的只读核实接口。后端代码及模拟边界测试不等同于所列用户场景已经通过端到端验收：真实 MySQL/代码源/集群/模型、网关和容量仍需联调。控制台前端按本次范围不实现；自动摘要尚未启用，专用 AI 审计和扩展管理按设计不在第一期实现。

## 环境配置

| 变量 | 说明 |
| --- | --- |
| `MYSQL_HOST` | 现有 MySQL 的 `主机:端口` |
| `MYSQL_USER` / `MYSQL_PASSWORD` | 复用现有账号；仅连接独立的 `zadig_ai` database |
| `MONGODB_CONNECTION_STRING` / `ASLAN_DB` | 复用现有 MongoDB 连接和配置数据库名，读取助手、模型集成及代理配置 |
| `HALMAN_USER_AUTH_ADDRESS` | user 的鉴权 gRPC 地址，默认 `user:8080` |
| `HALMAN_LISTEN_ADDRESS` | HTTP 监听地址，默认 `:8080` |
| `HALMAN_MAX_CONCURRENT_RUNS` | 每实例最大活动运行数，默认 `32`，范围 `1～1024`；聊天处理和确认后的操作共用预算 |
| `HALMAN_ADMISSION_WAIT_TIMEOUT` | 满载或入场锁占用时的短等待上限，默认 `2s`，允许 `0～30s`；`0` 表示不等待 |
| `HALMAN_DB_MAX_CONNECTIONS` | 每实例 MySQL 连接总上限，默认 `50`，范围 `2～10000`；业务池取六成向下取整，框架池取剩余部分 |
| `TZ` | 日聚合采用部署时区，示例为 `Asia/Shanghai` |

halman 直接连接 MongoDB，复用现有 repository 读取配置，不新增运行配置 HTTP 接口或专用服务 Token。数据库凭据由 Secret 注入，不向模型开放数据库工具，也不直接读写项目、服务等业务数据。

## 初始化与启动

初始化方式参考 user 服务：启动时使用复用账号创建 `zadig_ai` database（若不存在），再执行嵌入的完整建表 SQL；初始化仅作用于 `zadig_ai`。数据库版本至少支持 JSON，实际建表和查询需在目标 MySQL 版本验证。

配置好上述环境变量后执行：

```sh
go run ./cmd/halman
```

五张业务表的完整结构保存在 `core/repository/orm/init/mysql.sql`，使用 `CREATE TABLE IF NOT EXISTS`。框架原生表使用锁定版本的官方初始化逻辑，启动时补齐清理索引，初始化失败则不启动 HTTP 服务。

框架主模块和 MySQL Session 锁定为 `v1.11.2`，MySQL storage 子模块为 `v0.5.0`。

功能尚未上线，当前不维护增量迁移文件、不兼容旧版开发表结构，也不使用 GORM `AutoMigrate` 自动补列。重复启动不会删除表或重写已有业务数据；若已有旧开发表缺少字段，或仍包含已移除的 `framework_request_id`、`replaces_run_id`，结构检查会停止启动，需要自行重建开发库或手动对齐；不会自动删除字段或数据。正式上线后有结构变更时再设计升级方案。

默认业务池最多 30 个连接、框架池最多 20 个连接，每池空闲最多 5 个（且不超过该池连接上限）。模型调用不占用数据库事务。单个用户只允许一个活动运行，实例默认最多 32 个，聊天处理和确认后的操作共用名额。达到上限时，在当前 HTTP 请求内短暂等待，默认最多 2 秒；

有空位则接收，超时返回 HTTP 400/code 7217 和友好提示，客户端取消则立即停止等待。等待期间不占数据库连接或持有入场锁，不创建运行记录、不调用模型，不保证先来先执行；等待时长只约束入场阶段，不是整个接口的响应超时。已有请求仍可幂等查询。

三项环境变量均在进程启动时读取，未设置则使用默认值，格式错误或超出范围直接拒绝启动；修改后需重启。第一期不建设业务任务队列，不增加 `queued` 状态或排队容量配置；短等待请求随 HTTP 连接取消或进程退出而结束，重试仍使用原 `request_id`。数据库连接预算与执行并发分别设置，不能据此直接认定吞吐能力。

运行保存失败不会标记成功；启动及每分钟检查不在内存活动集合中的遗留运行，普通处理收敛为中断，已执行计划收敛为待核实，不重新调用模型或重放业务操作。恢复会重验行状态并维护根 Skill 的终态贡献，不补造丢失的 Token 统计。

第一期必须保持单实例，并使用 [Deployment 示例](../../../deploy/halman/deployment.yaml) 中的 `Recreate` 策略，不能手动扩容或并行启动第二个实例。独立示例要求已有 `halman-database` Secret 和共享的 `zadig-aes-key` Secret；使用 Helm 安装时由 chart 的现有数据库配置和 AES Secret 提供。示例未应用到集群，资源配额未经过默认 32 并发的容量验证。

## Swagger 文档生成

在仓库根目录执行 `make swag-halman`，生成 `pkg/microservice/halman/server/rest/doc` 下的 Go、JSON 和 YAML 文档；生成目录按现有服务惯例加入 Git 忽略。需要预先安装 `swag` 并加入 PATH。原有 `make swag` 继续只生成 aslan（包含 AI 助手统计及配置），`make swag-user` 生成 user。

## 模型选择与接口路由

aslan 保留以下前端配置接口：

- 对外 `GET/PUT /api/aslan/system/ai/assistant`：读取和修改 AI 开关、模型选择及保留天数均要求有效企业版，且当前登录用户为系统管理员。

halman 通过现有 MongoDB repository 直接加载助手开关、保留策略及所选模型，不经 aslan HTTP 接口。关闭 AI 或未选择模型时不查询模型凭据；模型失效时仍返回保留策略并记录模型错误，历史查询不依赖模型可用。代理配置按现有选择规则从 MongoDB 读取，不依赖 aslan 进程内缓存。配置查询有十秒超时，失败不记录或返回数据库、模型和代理凭据。

配置示例：

```json
{
  "enabled": true,
  "llm_integration_id": "已有模型集成的 ID",
  "history_retention_days": 90
}
```

`enabled` 是唯一的 AI 功能开关，默认关闭，由系统管理员开启。关闭 AI 后，新建会话、提交问题、重新回答、生成重试清单、推荐问题及确认执行返回 HTTP 400/code 7214；本人历史、运行快照、反馈、报告、SSE、取消、拒绝计划、删除和只读核实仍可用，并继续要求企业版、归属和相应权限。每次模型请求及每项写操作前复查最新配置；关闭开关阻止后续调用和未提交写入，不承诺撤回已发出的模型或业务请求。

业务写入仍须用户在确认卡片批准具体计划，通过会话归属、版本、有效期及当前资源权限检查；每项提交前复查 `enabled` 和资源权限。生成清单本身不会写入平台资源。

`/api/halman` 全部接口统一要求有效企业版许可证，包括普通聊天、本人历史、取消、删除及 SSE 建连。请求依次经过 user 登录校验、企业版校验、助手运行配置读取和业务处理。社区版、专业版、过期或其他非正常许可证返回 HTTP 400/code 7050；许可证查询失败返回 HTTP 500/code 500，不放行。`/healthz`、`/readyz` 保持独立，不要求登录或企业版。

内部调用直接使用既有服务发现：aslan 为 `config.AslanServiceAddress()`（默认 `aslan:25000`），user HTTP 客户端默认 `user:80`。适配器使用 aslan 原生 `/api/...`、`/openapi/...` 路径，不使用外部 `/api/aslan/...` 前缀。每次内部业务请求前都通过 user gRPC 检查原始用户 Token、撤销和 MFA；aslan 的资源操作仅携带实际用户身份。user 的权限查询仅允许 `auth-info`、`collaboration-action`、`collaboration-permission` 三个 GET 接口，使用既有 user 客户端的内部认证头，不对模型开放，不用于资源写入。保留超时、取消、响应大小限制、禁止重定向和写操作不自动重试。对外 `/api/halman` 仍由 Gloo 路由到 halman，内部调用不依赖该入口。

登录校验通过 `HALMAN_USER_AUTH_ADDRESS` 指向的 user gRPC `envoy.service.auth.v3.Authorization/Check` 实现，复用 Token 签名、有效期、撤销及 MFA 检查；只有 user 明确允许后才从 JWT 取得用户标识。不是只在本地解码 JWT，也不需要为每个普通聊天请求再调用 HTTP `auth-info`。`NewContextWithAuthorization()` 依赖调用链已完成登录校验，负责获取资源权限，不能替代这一步 user 鉴权。资源操作和管理员权限仍按需调用现有 HTTP 授权及业务接口。企业版检查在启动时直接装配现有 `commonutil.CheckZadigEnterpriseLicense()`，由该函数复用 plutusenterprise 客户端及现有企业版判定，halman 不拼接许可证请求或重复判断状态。沿用既有服务地址和 HTTP 客户端超时（60 秒），不新增许可证接口、配置项或缓存。

其他权限检查分布在业务服务和 DAO 中，没有新增可在角色管理中分配的“AI 助手使用”权限项：

| 入口 | 当前权限要求 |
| --- | --- |
| 普通聊天、推荐、新建会话 | 有效企业版下的有效用户登录态，且 `enabled=true` |
| 会话历史、运行快照、取消、反馈和删除 | 当前用户拥有该会话或运行；历史快照不重新要求业务资源权限 |
| 诊断、上下文复用、重新回答、核实 | 当前资源权限及实际归属；项目详情只允许系统管理员或已有项目权限的用户访问，不能仅用登录态判断，也不通过协作记录补授项目访问权限 |
| 确认写操作及重试清单 | 会话归属、当前计划及各动作对应权限，且 `enabled=true`；执行必须经过用户明确确认 |
| 查询助手配置 | 有效企业版，当前用户为系统管理员，不返回模型凭据 |
| 修改助手配置、查看完整报告 | 有效企业版，当前用户为系统管理员 |

业务权限不足返回 403，不把确认时的权限预检失败当作服务器错误。角色管理目前无法在有效企业版内单独禁用某个登录用户的普通 AI 聊天，这与业务资源权限是两个控制范围。

模型删除后，历史查看继续使用保留策略，发起新运行时报模型不可用。历史清理直接读取数据库配置，不受许可证到期或 AI 开关关闭影响；配置数据库不可用时暂停并按小时补偿。当前适配 OpenAI 兼容协议，支持流式响应和现有代理配置；不回退到环境变量中的模型或凭据。Anthropic、Azure 尚未适配；实际模型需支持工具调用，其能力及生成质量仍需联调验证。

对应 `helm-charts` 仓库的 `zadig` Chart 已接入 halman 的 Deployment、Service、ConfigMap 及 Gloo 路由，网关将 `/api/halman` 原样转发到 `halman:8080`，沿用全局用户鉴权及长连接超时。服务固定单副本，使用 `Recreate`，不挂载 Kubernetes ServiceAccount Token，复用现有 `zadig-aes-key` 的环境变量和 `/etc/encryption/aes` 文件；MySQL、MongoDB 配置复用已有 connections 值。控制台前端仍按范围不实现。

镜像使用 `global.image.registry` 和 `microservice.halman.image.repository/tag`，tag 为空时沿用 Chart 的 AppVersion，部署时需指定已发布镜像版本。`microservice.halman` 下的 `maxConcurrentRuns`、`admissionWaitTimeout`、`dbMaxConnections` 分别映射到三个运行配置环境变量，默认 32、2s、50；资源配额、全局调度和 Pod 标签/注解沿用 chart 习惯。出站业务请求直接访问 aslan，权限查询复用 user 客户端，不依赖 Gloo 网关地址或其 HTTP 端口。halman 使用 `TZ=Asia/Shanghai`，与现有 aslan 镜像默认时区一致。

错误响应统一复用 `pkg/tool/errors.ErrorMessage`，包含 `type`、`code`、`message`、`description`、`extra`。遵循现有约定：参数错误使用 HTTP 400/code 400；登录态、权限、资源不存在分别使用 HTTP 401/403/404 及同名 code；6xxx/7xxx 业务错误统一使用 HTTP 400，前端根据响应的 `code` 区分原因。许可证查询异常使用 HTTP 500/code 500；不在错误响应中返回数据库、模型凭据或原始上游响应。AG-UI 流建立前沿用该 HTTP 错误约定；建立后使用 `RUN_ERROR`，其 `code` 为相同错误码的字符串，`message` 为可公开的错误说明，流的 HTTP 状态保持 200，不继续发送旧的 `error` 事件。订阅故障不改变后台运行的实际状态。

| 业务错误码 | 含义 |
| --- | --- |
| `7050` | 企业版许可证不可用 |
| `7210` / `7211` | 读取 / 保存助手配置失败 |
| `7212` | 统计数据库、表、连接等待或查询不可用 |
| `7213` | 助手请求处理失败 |
| `7214` | 管理员关闭 AI |
| `7215` | 当前用户已有活动运行 |
| `7216` | 请求标识、计划版本或状态冲突 |
| `7217` | 执行并发容量不足，需稍后重试 |
| `7218` / `7219` | 模型 / 运行配置不可用 |
| `7220` | 访问 Zadig 资源失败；实际权限不足仍返回 403 |
| `7221` | 写操作结果待确认，不能直接重试 |

错误码在集中错误码表登记；每次响应创建独立错误对象，不修改共享模板。具体说明使用 `description`，不依赖错误文字判断重试或核实行为。

运行记录统一使用 `ai_run.id` 关联框架事件的 `request_id`。重新回答只保存原问题的 `question_source_run_id` 和 `answer_version`，不保存逐级替代链；是否为重新回答也据此判断，完成统计与异常恢复不会改变原 Skill 的业务状态。取消、拒绝、反馈、SSE 订阅前置检查及原问题/根执行定位采用只含标识、时间和 Skill 关联的轻量查询，不读取上下文、资源范围或计划 JSON；运行快照、确认、重试和核实继续按需读取完整清单。

分页响应为 `items` 和 `next_cursor`，后续请求使用 `cursor`；`limit` 上限 100。消息事件按时间、行 ID 倒序返回，附带 `run_id`、`question_run_id`、`answer_version` 和 `latest`。默认展示原问题及最新已保存的可用回答；

重新回答失败保留原回答，`include_versions=true` 可查看旧版本。过滤旧版本可能得到空页，仍须继续使用非空的 `next_cursor`。请求体不能指定执行用户，会话不绑定项目。

推荐接口接受 `page_type`、`project_key`、`env_name`、`service_name`、`production`、`workflow_name`、`task_id`、`job_name` 和 `batch`，响应含 `next_batch`。

统计统一由 aslan 的 `stat` 模块实现，Swagger tag 为 `stat`；助手配置的 Swagger tag 为 `system`。aslan 校验当前登录用户的系统管理员权限和有效企业版，直接读取 `zadig_ai.ai_usage_daily` 并计算指标，不调用 halman HTTP，也不加载 AI 开关、模型或聊天上下文。halman 继续负责日聚合写入、表初始化和过期清理，不提供报告查询接口。

Skill 分类表现按发布辅助、故障排查、实施辅助、巡检诊断的顺序固定返回四项，维度为 `category`；工作流和服务报错分析归入故障排查，项目和服务初始化归入实施辅助，环境巡检和效能诊断归入巡检诊断，发布辅助当前无对应 Skill。无数据分类返回零计数与空比例；普通聊天及未分类 Skill 不计入。分类通过 `ai_usage_daily.skill_id=ai_skill.id` 关联，分类内用户跨 Skill 去重，比例按分类总量计算；不按启停过滤历史贡献。日聚合仍按 Skill 保存，其他报告及概览估算口径不变。

aslan 需注入已有 `MYSQL_HOST`、`MYSQL_USER`、`MYSQL_PASSWORD` 配置，并与 halman 使用相同 `TZ`，示例为 `Asia/Shanghai`。统计首次查询时初始化 GORM 连接池，每个 aslan 实例最多三个连接、空闲一个、连接最长存活五分钟，不建库或建表，不执行迁移；统计库不可用不阻止 aslan 启动。由连接池控制最多三个并行 SQL 查询，其余在池内等待；连接等待和查询共用三秒预算，超时返回 HTTP 400/code 7212，数据库配置缺失、连接失败或聚合表尚不存在时返回 HTTP 400/code 7212，恢复后可重试。按 aslan 副本数累加连接预算，小池不能隔离共享 MySQL 的 CPU 或磁盘压力。

推荐只排列固定问题并返回候选上下文，不查询资源或替代执行时鉴权。报告使用 `from`、`to` 日期，默认最近三十天、最多保留三百六十五天，只读日聚合；无反馈时采纳率和估算人天为空。

四类报告使用独立路由、Handler、服务函数及响应模型，Swagger 在 `stat` 分组分别展示；鉴权和日期校验、指标计算及聚合 SQL 继续复用。所有响应都包含 `from`、`to`、`time_zone`；概览使用 `metrics` 返回整体指标，并包含 `estimation`、`estimated_saved_minutes`、`estimated_saved_person_days`。其他报告使用 `items` 列表及明确的日期、Skill 分类或用户维度字段；趋势和排行空列表返回 `[]`，Skill 分类始终返回四项。halman 停机或 AI 关闭时仍可读取已有统计。

概览额外返回 `previous`：紧邻当前周期、自然日数相同的上期，包含上期 `from`、`to`、`time_zone`、`metrics` 与估算节省分钟及人天；不按固定月长或秒数截取，跨月与夏令时仍按自然日计算。上期超出三百六十五天完整保留范围时返回 `null`，避免将已清理数据当成零值。只有概览提供上期，趋势、分类和排行仍仅返回当前周期。

所有报告指标增加 `total_tokens` 和 `model_usage[]`，后者包含 `model_id`、`model`、`input_tokens`、`output_tokens`、`total_tokens`，按模型集成 ID 和调用时的模型名排序，无数据返回 `[]`。`ai_usage_daily` 主键扩展为 `(date, user_id, skill_id, model_id, model_name)`；调用次数、耗时及 Token 从该次 `ai_run` 的模型快照写入对应模型行，任务终态、完成耗时和反馈继续写入空模型维度。修正任务贡献时仅更新空模型行，汇总时跨模型求和并对用户去重，不能按模型重复计算任务数。模型信息随日聚合保留三百六十五天，不依赖已到期的运行记录或当前模型配置，不增加表。

概览 `total_users` 通过现有 user SDK 查询系统当前用户总数，与 `metrics.active_users` 配合计算团队渗透率；它是当前用户数，不是上期历史用户数。排行批量查询最多二十名用户的当前名称，返回 `user_name`；已删除或名称为空的用户回退为 `user_id`。user 查询失败返回统计失败，不能把系统用户总数默认为零或将查询故障当成用户已删除。SQL、连接等待与 user 查询共用三秒请求预算。分类和排行的模型明细仅查询报告实际返回的分组。


内置 Skill 完整定义及设置保存在 MySQL `ai_skill`，不保存到 MongoDB。`core/skill/<skill_id>.md` 通过 `go:embed` 打包作为发布源，启动时事务同步名称、分类、说明及正文，保留启停和追加规则，定义未变不更新；未来自定义来源不被覆盖。表包含 `id`、`source`、`name`、`category`、`description`、`content`、`enabled`、`custom_rules`、`created_at`、`updated_at`，没有默认提问字段，也不参与聊天到期清理。

管理接口的 GET 列表及 PUT 保存响应按本次请求的系统语言返回展示副本：`name`、`description`、`content` 支持中英文，新增 `category_name` 作为分类展示名，`category` 始终保留数据库原值用于分组和统计。中文或未知系统语言返回数据库原文；英文展示元数据及六份 `core/skill/<skill_id>.en.md` 随代码维护、通过 `go:embed` 打包，仅按内置 Skill ID 选择，不同步到数据库或用于模型执行。中文原始定义、管理员的 `custom_rules`、启停状态、ID 和时间戳均不因语言切换而修改。未知内置定义及其他来源的名称、说明和正文回退原文，四个已知分类的展示名独立转换。没有新增数据库字段、查询或模型翻译调用；英文展示资源随中文定义更新同步维护。前端应使用 `category_name` 展示分类，继续使用 `category` 分组。

管理接口复用用户登录与许可证检查，并通过 user SDK 校验系统管理员；AI 总开关关闭仍可管理。GET 返回 `items`，PUT 两项均必填，规则最多 8000 字节 UTF-8，拒绝额外字段；恢复默认保存 `{"enabled":true,"custom_rules":""}`。不支持新建、删除或修改内置正文。未知 ID 返回 404，读写失败为 HTTP 400/code 7219，不回退默认配置。

每次生成读取一次完整配置快照并组合对应中文正文和追加规则，同次运行不变；后续补问和重新回答读取新规则。停用只禁止新任务，过滤工具声明并在业务工具中校验；合法既有补问、重试、重新回答及确认仍可继续，旧清单不因规则更新失效。补问须指向本人同会话、仍等待输入或确认的根执行，不能借用已结束任务绕过停用。追加文字不扩大权限或跳过确认，不保证强制校验任意命名规则；升级保留的追加规则可能需要管理员检查兼容性。全局 AI 开关仍按原逻辑限制后续调用。

界面约定（本次不实现前端）：左侧四类分组、停用标记及空态；右侧只读展示随系统语言切换的名称、分类展示名、说明与 Markdown 正文，单独编辑启用和原文追加规则。恢复默认先修改表单，保存才提交；切换未保存内容时提示。不提供默认提问、新建、删除或内置正文编辑入口。现有推荐问题保留原提问逻辑，只过滤停用项；无可用项返回空列表及 `next_batch=0`，不重复补齐。

原报告融合：环境巡检调用原 `POST /api/environment/environments/{name}/analysis` 的 `result`，固定触发来源为 `ai-assistant`；历史复用原接口，默认五条、每页最多二十条、页码最多一万，按项目、环境和生产属性隔离。补充服务证据复用原采集函数，限当前环境三个服务，不另计 Skill。空报告或失败不代表健康，也不计完成。

效能诊断调用原 `POST /api/stat/v2/ai/analysis`，仅将 `answer` 返回模型，过滤内部提示词、输入数据及估算 Token。系统管理员或有 `SystemActions.DataCenter.ViewInsight` 权限即可，不要求项目权限；名称解析在 aslan 内按同一权限进行。只接受指定项目，默认三十天、最多十个项目和九十天。完整显式范围生效且不由旧解析覆盖，仅传问题的旧调用保持原行为。系统级范围记录在现有 `resource_scopes.system_action`，上下文及重新回答按该权限复查，历史聊天快照查看规则不变。

不增加证据模式或新数据接口，原功能继续使用原模型，助手使用原报告回答。仅原报告调用放宽到三分钟，普通 HTTP 仍为十秒；同次运行缓存相同参数的报告及失败，默认范围锚定运行时间，不自动重复调用。超时或取消可能无法停止原模块，可稍后查原结果。聊天仍存 MySQL，原巡检历史继续落原 MongoDB。两种新 Skill 采用十五分钟基准；原模块未提供完整实际模型用量，不将旧估算 `token_num` 混入助手 Token 统计。巡检不配置计划、不发送定时通知、不自动修复。

运行请求示例：

```json
{
  "request_id": "chat-20261029-001",
  "message": "请解释一下 Zadig 服务初始化的前置条件",
  "context": {
    "page_type": "project",
    "project_key": "order-system"
  }
}
```

`request_id` 实际仅允许 1～64 位字母、数字、横线和下划线；同一用户重试必须保持会话、正文和上下文一致，改变参数需使用新标识。页面快照作为候选交给模型，工具根据实际资源归属及当前权限重新验证；明确指定的目标优先，不能拼接不相符页面的项目、工作流和任务。

历史快照的本人读取不重新要求资源权限，带资源范围的历史进入新模型上下文时重新鉴权。补问使用新 `request_id`，并通过 `skill_execution_id` 关联本次业务目标的根运行；超过保留期的根执行不能续用。

六个 Skill 均通过现有 `ai_run.plan` 保存参数，补问不新增表或公共接口。初始化使用 `draft` 保存清单参数，其余四个 Skill 使用 `input` 保存查询条件；只存参数和 `missing_fields`，不额外保存报告。参数不全也先调用业务工具，返回 `awaiting_input` 和根执行 ID；后续请求携带相同 `skill_execution_id`，工具自动检查归属、保留期及当前权限，恢复并合并本轮输入。`read_saved_operation` 可用于显式查看草稿，不是继续任务的必经步骤。更换页面不覆盖草稿，更换项目、工作流或环境会清除依赖的旧目标。只读查询的空字段视为未提供，生产属性用可选布尔值区分省略与明确 false；效能项目列表按本轮整体替换，未改动的时间范围保留。补问和仅恢复参数不计完成，查询仍须重新鉴权并取得有效证据。

批量初始化记录用户要求的 `expected_service_count`（最多二十）；例如要求三个服务，即使尚无名称也先记录总数。共享仓库信息只问一次，由模型填入各服务；后续按服务名局部合并，省略或空列表不删除服务，明确移除用 `remove_services`，改变总数须显式更新 `expected_service_count`。修改 web 的路径不会丢失 api、worker 的配置；模板必填变量按服务返回缺失项，未知变量、凭据和非法类型仍拒绝。初始化支持显式 false，null 清空可选配置，空构建列表清空构建；环境和构建参数允许分轮补齐。生成新草稿后旧待确认卡片同步失效，参数齐全仍须预检并重新确认。

重新回答时，初始化仅解释原操作快照；诊断沿用原查询参数重新取证，不改写原草稿或操作清单。

确认统一使用 `POST /api/halman/runs/:id/confirmation`，请求如 `{"version":1,"decision":"confirm"}` 或 `{"version":1,"decision":"reject"}`；没有同义的 `/confirm` 路由。它授权执行卡片中列明的具体业务动作，不表示认可模型回答。会话仅支持无请求体的 `DELETE /api/halman/conversations/:id`，指定要删除的会话 ID，并校验当前用户归属；不提供清空全部会话的接口。删除会话不删除 Zadig 资源。

`cancel` 与 `confirmation` 的职责明确分开：

- `cancel` 仅停止 `running/executing` 运行，或放弃同一 Skill 当前最新的 `awaiting_input` 补问；`pending_confirmation` 必须通过 `confirmation` 的 `decision=reject` 拒绝，直接取消返回 HTTP 400/code 7216。已经 `cancelling` 或进入终态的重复取消不改写持久化状态。
- 拒绝只处理当前待确认清单，须在同一事务中核对 `active_plan_run_id`、`plan_version`、`plan_status` 及根业务状态 `pending_confirmation`；被替换的旧清单、错误版本及已经开始执行的清单返回 HTTP 400/code 7216。当前清单即使已过期也允许拒绝关闭，但不能确认执行。同一当前版本已经拒绝后再次拒绝幂等返回 204，不重复修改统计；计划指针变化后，旧请求不再视为重复拒绝。
- 取消和拒绝按会话、Skill 根执行、目标运行的顺序加行锁，与确认、生成新清单和删除串行化。状态与 Skill 聚合贡献在同一事务中更新；事务失败整体回滚。`cancel` 只在事务提交成功后停止后台上下文，拒绝不调用后台取消函数。
- 放弃补问时校验根业务状态及同一 Skill 最新的非重新回答运行，旧补问不能覆盖新进展；该 Skill 尚未执行的旧待确认清单同步失效，防止放弃后再次确认。其他 Skill 的进展不参与这项最新运行判断。仅增加必要的标量查询，沿用已有会话及 Skill 索引，不读取计划或上下文 JSON，不新增数据库表。

| 接口 | 处理对象及行为 | 是否提交业务写操作 |
| --- | --- | --- |
| `regenerate` | 原问题和上下文，生成新的回答版本，失败保留旧回答 | 否 |
| `retry` | 已失败且结果明确的操作计划，保留成功项，生成失败项的新待确认计划 | 本次不提交，再次确认后才执行 |
| `reconcile` | 结果未知的操作，只读查询实际资源并更新运行记录，无法证明时仍为 `unknown` | 否，不重新执行原操作 |
| `events` | 本人运行的 SSE 事件流，推送增量回答、状态、待确认卡片及逐项结果 | 否，订阅不触发或重跑任务 |

### AG-UI 交互约定

会话创建、列表、历史、删除和运行管理保留 REST；提交问题统一使用 `POST /api/halman/conversations/:id/runs`，采用 AG-UI 请求和事件流，不保留 `/api/halman/agui` 别名。新建会话后，将会话 ID 放入路径和请求体 `threadId`，两者必须一致，不一致时在启动运行前返回 HTTP 400/code 400；继续提问沿用同一会话，与当前项目或页面切换无关。

请求采用 AG-UI 的 camelCase 字段，例如：

```json
{
  "threadId": "已创建的本人会话ID",
  "runId": "chat-20261104-001",
  "messages": [
    {"id": "user-message-001", "role": "user", "content": "帮我分析工作流失败原因"}
  ],
  "state": {},
  "tools": [],
  "context": [],
  "forwardedProps": {
    "page_context": {"project_key": "demo", "workflow_name": "build", "task_id": 12}
  }
}
```

`runId` 对应已有的幂等 `request_id`：1～64 位字母、数字、横线或下划线。同一标识重复提交时，问题、页面候选及 Skill 根关联必须一致；不同用户相互隔离。只读取 `messages` 最后一条带 `id` 的纯文本 `user` 消息，单条问题最多 16000 字节，请求体最多 1 MiB。客户端可携带历史和 `state`、`context`，但这些内容不进入模型上下文、不作为授权依据；模型历史由服务端按原有权限、版本及保留期规则构建。客户端工具、工具结果和 `resume` 暂不支持，非空时明确拒绝；写操作仍通过版本化 `confirmation` 接口确认。补问在 `forwardedProps.skill_execution_id` 中传递原根执行 ID。

AG-UI 的 `RUN_STARTED.runId` 在 POST 响应中回显请求的 `runId`；实际运行 ID 为 `STATE_SNAPSHOT.snapshot.run.id`，后续 `confirmation/cancel/feedback/regenerate/retry/reconcile` 和 GET 恢复订阅均使用这个实际 ID，不能混用。恢复订阅的生成阶段使用原请求标识，确认执行阶段使用 `<原请求标识>:plan:<计划版本>`，区分生成清单与执行清单。相同 POST 只关联原运行，不重新提交模型或业务操作；已结束运行只发送当前快照及生命周期边界，回答正文通过历史接口恢复。

所有流式入口仅输出 AG-UI 事件，SSE 帧由 SDK 编码；不再使用自定义 SSE `event:` 名称或 `[DONE]`。SDK 附带的 `id` 和 `timestamp` 仅为传输元数据，不是数据库游标，不支持按 `Last-Event-ID` 重放：

| 内容 | AG-UI 事件 |
| --- | --- |
| 生命周期 | `RUN_STARTED` → `RUN_FINISHED` 或 `RUN_ERROR` |
| 流式回答 | `TEXT_MESSAGE_START` → `TEXT_MESSAGE_CONTENT` → `TEXT_MESSAGE_END`；同一消息沿用框架 `messageId`，由框架处理完整消息与流式分片的合并和结束 |
| 模型可见推理 | `REASONING_START` → `REASONING_MESSAGE_START` → `REASONING_MESSAGE_CONTENT` → `REASONING_MESSAGE_END` → `REASONING_END`；由框架维护消息关联与边界，无推理内容时不发送 |
| 运行快照 | `STATE_SNAPSHOT`，`snapshot.run` 为完整运行快照 |
| 操作进度 | `STATE_DELTA`，JSON Patch 替换 `/run/plan/items/<下标>` |
| 待确认清单 | `CUSTOM`，`name=halman.confirmation_required`，`value` 为计划版本、有效期和清单；只展示候选卡片，等待快照状态变为 `pending_confirmation` 才启用确认 |
| 会话标题 | `CUSTOM`，`name=halman.conversation_title`，`value` 包含 `conversation_id/title` |
| 恢复提示 | `CUSTOM`，`name=halman.resync_required`，`value.run_id` 为实际运行 ID；随后断开，调用方重新获取历史和状态，再按需订阅 |
| 保活 | 每 15 秒发送 SSE 注释 `: heartbeat` 并复查登录态，不产生业务事件或数据库写入 |

可见推理展示通过框架 `WithReasoningContentEnabled(true)` 开启，不调整模型推理模式、推理强度或 Token 上限，也不额外调用模型。仅展示模型实际返回的 `reasoning_content`，不会获取模型未公开的内部思考。历史消息沿用原生消息中的 `reasoning_content` 恢复推理内容，遵循相同的归属、回答版本和保留期规则；不新增表或逐 Token 写入。前端分别展示推理和正文，不能把推理内容当作操作确认或成功依据。客户端需支持上述 `REASONING_*` 事件；所锁定 Go SDK 的通用 JSON Decoder 尚未注册这些事件，服务端使用官方事件类型及 SSE Writer 输出，协议测试直接校验官方推理事件类型。

`RUN_FINISHED.result` 保留运行快照。`pending_confirmation`、`awaiting_input`、`unknown` 或 `cancelled` 均不能解释为 Skill 成功；完成任务仍由既有业务状态及日聚合决定。协议的生成阶段在等待用户时结束，确认后的执行通过 GET 另行订阅；不引入草案中断协议代替后端确认检查。

订阅在后台执行启动前建立；恢复订阅先注册连接再读取快照，避免漏掉结束通知。执行器结束后，再读一次运行快照恢复逐项结果。重连不执行、不重放已错过的 token，客户端应先结合运行状态和历史消息恢复已保存内容。每个运行最多保留两个订阅连接，超出时淘汰最早的连接并向其发送恢复提示，最新连接始终建立成功，断线不取消运行；慢连接缓冲满或运行阶段变化时发送恢复提示，不伪造成功终态。没有观察到终态的断流需要重新查询，不能直接当作成功或失败。订阅数与全局执行并发是两回事，订阅被淘汰不返回 7217。

协议层复用官方 AG-UI SDK 的 `RunAgentInput`、事件类型和 SSE Writer，以及 tRPC-Agent-Go 自带 Translator，不自行维护标准协议 DTO、消息编号或文本消息边界。AG-UI 子模块固定到与现有框架 v1.11.2 相同的提交，核心框架版本保持不变。Halman 仅适配 Zadig 页面候选、业务状态、确认卡片及恢复订阅，复用原 Runner、执行器、鉴权和原生消息存储；框架提前产生的运行完成事件不作为业务终态，默认开启模型可见推理事件，工具原始结果和参数不直接公开。不新增事件表或逐 token 持久化。标准 AG-UI HTTP 客户端可以向 POST 入口提交上述文本请求；恢复订阅及 Zadig 自定义卡片需要客户端按上述约定处理。参考 [AG-UI 架构](https://docs.ag-ui.com/concepts/architecture) 和 [事件定义](https://docs.ag-ui.com/concepts/events)。

会话创建时按系统语言使用“新会话”或“New conversation”，首条问题接收后立即以去除首尾空白的前四十字作为临时标题，并同步保存 `title_source_at`。首轮得到有效回答或进入补问、待确认状态后，复用本轮选定模型额外按本轮系统语言生成一次标题，中文建议十二至二十字，英文保持简短，均最多四十字；只输入经过凭据脱敏的首条用户问题，最多两千字，不传回答、日志或工具结果，也不注册工具。调用前复查用户登录态、最新 AI 开关和模型可用性；标题任务与本轮共用执行名额，最多十秒，不重试。正文已流式发送，但本轮终态可能因此延后最多十秒。

标题请求失败、超时、输出无效或保存失败时保留截取标题，不将本轮回答标记为失败；请求期间取消整个运行仍按正常取消处理。标题 Token 计入本轮及日聚合，不额外增加运行次数或 Skill 完成数，不保存额外聊天消息。写回只允许本人未删除且标题来源时间仍匹配的会话，成功后发送 AG-UI `CUSTOM` 事件 `halman.conversation_title`；断线后可重新读取会话列表获取标题。后续提问、重新回答及重试不再次生成标题。来源消息到期时，后台从保留期内消息截取标题，不另行调用模型。

## 业务调用与确认

六个 Skill 的定义和工具提示均为中文，但面向用户的模型输出遵循本轮系统语言，工具集合固定，不内置 Shell、SQL、任意 HTTP、kubectl、clone 或仓库写工具。aslan 业务 HTTP 使用现有 `config.AslanServiceAddress()`，仅透传当前用户 Authorization，不携带服务 Token；权限查询限定三个只读 user 接口，复用现有 user 客户端及内部认证头。专用模型凭据不会发送给业务接口。查询目录只暴露必要元数据，剔除原始 YAML、脚本及凭据。

- 工作流：校验任务归属，读取当次任务状态和错误；失败步骤日志每次最多三份，单窗口默认 200 行、最多 500 行，支持向前分页到 5,000 行。接口不会重跑任务。S3 日志仍需下载目标步骤文件到 aslan 临时文件后流式扫描，不会把全文件加载到模型或内存。
- 服务：校验环境实际生产属性和服务归属，读取运行状态、发布历史、最多三个容器的当前及上次退出日志和 Pod 事件。已有容器日志接口的片段模式检查 Pod 和容器属于目标服务；未取得证据时返回不可用说明。
- 初始化：每批最多二十个服务，支持 GitHub/GitLab 配置、YAML 模板、Git Chart、Chart 仓库和 Chart 模板，以及已有 Git values 文件。读取配置通过代码源文件 API，不 clone；Chart 名称、具体版本、变量类型和模板版本由程序校验。
- 构建与工作流：未选择已有构建模板时跳过构建；构建绑定实际服务组件，不能覆盖同名构建。工作流仅调用原有 `AutoCreateWorkflow`，不修改其逻辑，不执行构建发布。

### 业务查询接口复用

下表使用网关路径，业务请求均透传当前用户身份。已移除五条 `/api/logs/log/assistant/...` 专用查询路由，仅扩展原有两条日志接口。

| 能力 | 复用接口 | 调整 |
| --- | --- | --- |
| 工作流步骤日志 | `GET /api/aslan/logs/log/v4/workflow/{workflowName}/tasks/{taskID}/jobs/{jobName}` | 增加可选 `format=excerpt`、`projectName`、`offset`、`limit` |
| 服务 Pod 列表 | `GET /openapi/environments/{name}/service/{serviceName}/pods?projectKey=...` | 直接复用；生产环境使用已有 `/openapi/environments/production/...` 路径 |
| 容器日志 | `GET /api/aslan/logs/pods/{name}` | 增加片段模式及 `previous`，约束已有 `tailLines`；片段模式要求 `serviceName` 校验归属，不新增 `production` 参数 |
| Pod 事件 | `GET /api/aslan/environment/kube/pods/{podName}/events` | 直接复用已有 `projectName`、`envName`、`production` 参数 |
| 默认工作流核实 | `GET /api/aslan/environment/environments?projectName=...&production=false`、`GET /api/aslan/workflow/v4?project=...` | 按实际非生产环境核对 `<项目>-workflow-<环境>` 和 `<项目>-ops-workflow`，不新增 `default_workflow_status` |

两条日志接口未传 `format=excerpt` 时保留原字符串或流式行为。片段模式校验当前权限和实际资源归属，默认 200 行、最多 500 行、单次最多 48 KiB；工作流可按 `next_offset` 向前分页，`offset` 最大 5,000。容器日志从数据库中的实际环境记录判断生产属性；无法唯一定位时拒绝读取。容器日志仅支持最近窗口，不分页，`total_lines=-1` 表示完整总行数未知，`next_offset=0`，`truncated=true`；不能将 Kubernetes 截断后的局部行数当作全部日志。

工作流诊断直接复用原任务详情接口，不增加查询参数、返回字段或 aslan 配置提取函数。halman 从原响应的 `stages[].jobs[].spec` 中按白名单提取仓库、分支、提交、服务、部署目标环境名称、镜像及 Chart 版本，保留原任务编号和创建时间；不直接读取业务 MongoDB，也不用当前配置补齐历史。

默认最多提取三个失败或超时步骤，用户指定步骤时由 halman 本地筛选；单步骤最多 8 KiB，仓库、镜像及 Chart 列表分别最多二十项，缺失、超限和截断明确说明。不透传原始 `spec`，不返回凭据、变量值、脚本正文、完整 YAML/values，以及原接口补充的当前环境 `production`、`env_alias`。原详情没有返回的构建环境和工具版本不推断；证据不足时结合有限日志分析并说明限制。

每次模型调用前，按运行 ID 批量读取本轮及实际载入历史的 `resource_scopes`，覆盖此前读取的全部资源，不仅检查最后一个页面目标；沿用最多六十条历史事件窗口，最多涉及六十一个运行，不扫描聊天正文。来源记录缺失或任一权限撤销后停止本次生成，本人历史快照仍可查看。目录结果继续不进入后续历史上下文。

纯权限复查只使用 user 的现有授权接口：`auth-info` 检查管理员、工作流查看、测试/生产环境查看及效能洞察权限，`collaboration-permission` 检查具体工作流或环境的查看动作，项目访问仅依据系统管理员标志或 `auth-info.project_auth_info` 中已有的角色及全局只读权限；缺少项目条目时拒绝，不再补查授权项目集合。仅编辑权限不能放行。同次复查共用一份权限快照，并对工作流、环境的相同协作授权去重，下一次模型调用重新查询。不增加接口或参数，不读取项目统计、任务详情或环境配置。实际业务查询仍由 aslan 鉴权及校验归属；日志窗口直接复用原片段接口的权限和任务、步骤归属检查。

环境详情沿用已有 `production` 查询参数，数据库按该属性区分同名生产和测试环境，响应明确返回环境记录的 `production`；`is_prod` 仍为集群属性。halman 使用可空布尔接收实际生产属性，缺失、目标不符时拒绝生成或执行修复清单，不把缺失值当成 false。

服务诊断最多读取三个容器的当前及上次退出日志，每个 Pod 单独查询一次事件，最多保留二十条事件。日志和事件共用 64 KiB 的模型证据预算，失败或超出预算时明确标记不可用；Pod 列表最多保留五十条，截断后的列表不能用于证明重启或回滚全部完成。

模板选择优先使用用户指定的完整名称，例如“使用 Go 标准构建模板”，由 halman 解析为模板 ID。YAML 和构建模板复用 aslan 原有列表、分页和详情接口，不增加 `keyword` 参数或数据库搜索条件。`query_catalog.keyword` 在 halman 内按完整名称精确匹配当前页，每页五十项；未匹配时按 `next_page` 继续查询，零表示末页。找到精确匹配后查询详情；名称不明确时列出候选，有歧义时补问，不擅自使用相似模板，也不把当前页为空当作模板不存在。

其他资源通过 `query_catalog.keyword` 复用原接口名称查询，最多 128 字节。项目复用 `filter`，仓库与分支复用 `key`，其他完整目录在工具侧按名称过滤，默认最多展示五十项。GitHub 完全沿用原有适配器实现：仓库读取本人可访问的完整列表并按所属用户或组织过滤，不新增关键词过滤或结果分页；分支沿用原有正则匹配，不新增分页，不扩展远端关键词搜索，保留资源量较大时的读取开销。halman 优先复用 aslan 的现有能力，尽量不修改其功能和函数；确需修改或新增接口时，先说明范围并取得确认。

Helm 模板读取现有详情接口的 `metadata_only=true` 模式，返回来源、修订号、内容摘要及变量，不下载模板文件；预览、确认及实际提交前使用同一份定义计算指纹，变量不变但内容摘要改变也会使旧清单失效。缺少摘要时拒绝生成或执行，提示先更新原模板；原变量接口响应保持兼容。

同一轮初始化预览、重试清单生成或一次确认校验内，对相同用户、路径和查询参数的模板详情、代码源列表及项目已有服务列表合并读取；单阶段最多保留 1 MiB 响应，超出后沿用直接查询。失败响应、授权接口、业务写入和其他查询不缓存，命中前仍校验登录态。阶段结束即释放，不跨补问、确认或运行复用；每项实际提交前仍重新查询模板指纹、权限和服务冲突，不能沿用预览或确认阶段的数据。

服务诊断首次必须记录 `goal=diagnose/restart_service/rollback_environment`，保存在现有 `plan.input` 中；仅诊断可由有效证据及回答完成。修复目标取得证据后仍为等待状态，必须生成清单并由用户确认，最终按实际执行结果计完成；不能在同次执行中将修复降级为仅诊断。直接准备修复同样记录目标，缺少回滚版本则保存草稿补问；重新回答只解释原目标，不改变或重复统计完成。

清单保存在 `ai_run.plan`，三十分钟有效；`ai_run.active_plan_run_id` 在根运行指向当前版本，旧清单失效。新建项目包含当前用户管理员，默认私有；创建环境明确提示实际部署影响。模板版本变化后重新生成清单。第一期暂不分析服务初始化触发的自动部署影响，不读取或修改自动部署策略；现有导入接口仍按平台配置执行，不能承诺导入没有部署副作用。

确认请求示例：

```json
{"version": 1}
```

确认、取消、删除按会话、根运行、当前运行顺序串行判定。每项写入前先在短事务中领取为 `submitting`，事务提交后才发 HTTP；取消阻止未领取动作，不承诺撤回已提交操作。逐项保留成功结果，失败不回滚已成功资源，前置失败的动作标记 `blocked`，独立动作继续。

异步环境部署轮询实际状态；重启等待原实例更替且新实例就绪，回滚同时核对对应本次运行的发布记录。超时、含部分失败的服务导入和不能证明完成的结果保留为 `unknown`，不计完成、不自动重放。写入成功响应后发生取消、失权或查询失败，也不能视为未执行。

`reconcile` 透传当前用户身份，先重新鉴权，再只读查询实际资源、配置来源、创建时间、就绪状态及对应发布记录。证据不足、来源不一致或资源返回 404 时继续保留 `unknown`，不能将暂时查不到当成可以重放的证明；有明确平台失败终态时才收敛为失败。

`reconcile` 保留为显式的结果核实入口：写请求超时或进程中断时，平台可能已完成操作，不能直接认定失败或重发。它重新校验当前资源权限并查询实际状态；普通运行快照读取只查看保存结果，不会隐式触发这些查询。核实能力用于恢复 `unknown`、安全决定重试及完成统计，当前不合并到历史查询接口。

默认工作流通过已有非生产环境列表和工作流列表核对固定名称，不新增状态字段，不调用创建逻辑；需要完整环境及工作流查看权限，不能将协作权限下的可见子集当成全部。核实不会自动执行失败项；过期、被替代或并发变化的快照不能写回状态。

`retry` 只接受已失败、仍有效且没有未知结果的当前计划。成功项及结果保留，失败、阻塞项转为待执行；重新检查权限、冲突及模板，修复动作重新读取实际快照，再生成三十分钟有效的新待确认运行，共用原 `skill_execution_id`。

只有用户确认后执行器才提交待执行项，原请求 ID 幂等返回同一清单。已有同名服务、构建或环境不会被重复创建或覆盖；例如已创建但部署失败的环境，需要先在平台处理已有资源，不能使用创建接口盲目重试。重试入口不调用模型，不增加模型调用量；

若清单保存成功但框架聊天记录保存失败，接口会明确提示并返回已保存的运行 ID，不能因此重放平台操作。

完成数来自 Skill 根状态在同一事务中的贡献更新，同一业务目标的补问、重试和多个服务不重复计数；诊断只有必要查询和最终助手回答都完成才成功，初始化只有清单全部完成才成功。根状态改变与日聚合贡献在同一业务事务内更新，失败后完成撤回旧终态贡献，再计入一次成功。

## 存储与验证边界

业务 DAO 位于 `core/repository/orm`，使用与 user 服务相同版本的 GORM 和 MySQL dialect。普通读写使用 GORM API，涉及行锁、状态转换、游标分页、聚合和分批清理的 SQL 通过 GORM `Raw` / `Exec` 执行。

所有查询和事务均传递请求上下文，确认、取消和删除保持显式短事务及原有锁顺序；不依赖 GORM 默认事务。

GORM 复用受限业务连接池，`Store.DB` 和 `Store.SQLDB` 对应同一个池；后者仅用于健康检查、连接统计和关闭。框架消息仍由官方 MySQL Session 写入，不重写框架存储。默认业务池上限 30、框架池上限 20，合计上限 50；不复用 user 服务进程的连接池。

GORM SQL 日志关闭，避免记录聊天内容及配置参数；初始化使用完整 SQL 文件，不使用 `AutoMigrate`。

正文只保存到框架 `session_events`，不复制到业务表。模型上下文最多读取最近 60 个事件，经过期及资源范围过滤后，将原问题与最新回答作为同一逻辑轮次限制到 64 KiB；缺少原问题或工具调用/结果不配对的截断轮次整轮舍弃。带业务资源范围的历史只在目标一致且所有必要范围当前鉴权通过时使用；

来源未经验证的摘要仍不启用。单条用户消息最多 16,000 字节，消息事件最多 256 KiB，请求体最多 64 KiB。

历史读取立即排除超过保留期限的消息与运行；模型失效和资源权限变化不隐藏本人已保存的未到期快照。物理清理由单一后台工作者在启动及每小时补偿，单轮最多十分钟，逐批 SQL 最多两秒、间隔 200 毫秒，框架正文每批最多 32 行，普通元数据每批最多 500 行、运行批次最多 50 行。

数据库连接已占满或发生错误时暂停，下一轮补偿；不启用 SDK 整会话 TTL 删除。删除会话也逐表分批清理，并重建已到期的标题。

保留期内未核实的写结果阻止删除及整会话清理；超过根 Skill 保留期后入口失效，未知记录转为 `expired`，不证明业务成功或失败，不再阻挡过期根记录清理，近期补问正文仍按自己的生成时间保留。日聚合保留三百六十五天；可清理表采用固定白名单，不触碰业务审计及后续永久 AI 审计。

halman 在模型运行开始、结束、取消请求受理和异常恢复时记录 INFO 日志，以 `run_id` 串联；开始记录请求、会话与模型标识，结束记录 Skill、处理结果状态、结果保存是否成功、耗时与 Token，异常恢复记录旧、新状态。结束摘要中的 `result_status` 为本次处理结果，不代替数据库中的最终状态；最终保存失败时记录一次 ERROR，包含错误类型、MySQL 错误码及超时标志，不输出可能包含输入值的原始数据库异常。正常运行仅增加开始、结束两条 INFO，不逐 Token、逐工具成功或逐消息写入日志；不记录聊天正文、工具参数、操作清单或凭据。

工作流步骤标识单独允许中文，并按路径段转义；项目、环境及其他资源标识继续沿用原校验。自动日志采集和后续窗口读取使用相同的步骤名校验；缺少步骤名时明确提示补齐，不返回通用资源标识错误。不修改 aslan 接口、参数或鉴权逻辑。

halman 清理周期的结构化日志中的 `maintenance` 包括最近尝试、成功、进展时间、耗时、影响行数及批次、暂停原因、最早到期/已删除数据及超过二十四小时积压标记，并附带 `database_pool` 连接池状态，积压继续输出告警。这些状态仅保存在当前进程内，重启后由下一轮重建；目前未接外部通知系统。真实 MySQL 的删除效率、磁盘回收及长时间积压仍需目标环境验证。

单元测试覆盖会话归属、请求去重、取消和删除事务、消息分页、回答版本及上下文过滤、草稿恢复、持久化失败、凭据隔离及模拟流式模型，并覆盖目标归属、配置来源限制、日志窗口、凭据脱敏、模板参数及版本、过期/被替换清单、领取及取消、成功项不重放、核实保留未知、反馈去重和事务回滚、报告权限和空指标、异常恢复、清理保护及 Skill 完成去重。

SQL mock 测试不等同于 MySQL 锁竞争或性能验证；实际数据库初始化、登录链路、真实模型和网关 SSE 仍需联调。

## AI 输出语言

助手和 AI 代码审查统一使用系统配置 `language`，支持 `zh-cn`、`en-us`，兼容大小写；空值或未知值默认中文。halman 与助手设置共用一次 MongoDB 查询加载语言，数据库读取失败不伪装为默认配置。

每次助手生成或确认执行固定语言快照，补问、重新回答和下一次请求使用最新配置。模型回答、自动标题、六类推荐的标题和提问文本，以及新生成的确认说明、操作结果、状态和助手专属错误文案支持中英文；历史消息、标题和已保存清单不重新翻译。代码、日志、资源名称、结构化枚举及公共平台错误响应保留原文。中文 Skill 和追加规则不能覆盖本轮输出语言。

代码审查删除独立的 `output_language` 配置字段。创建任务时将系统语言通过现有环境变量和 `--language` 参数传给审查程序，报告收集不变；摘要、行内评论和归档说明按报告已有的 `metadata.language` 选择文案，缺失或未知时默认中文，不新增步骤语言字段。保留原评论标记、指纹、反馈和历史摘要识别。旧 MongoDB 字段不批量迁移，下一次保存配置自然移除，旧请求携带该字段时忽略。

不修改前端和审查程序仓库；前端独立语言下拉框需后续移除。自动测试使用模拟模型和数据库，真实模型遵循效果和审查镜像需联调验证。
