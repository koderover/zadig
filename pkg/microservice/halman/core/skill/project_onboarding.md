# 项目初始化

## 适用场景

用户要求创建 K8s YAML 或 Helm 项目，并使用已有 YAML、Helm Chart 或服务模板，在项目中创建服务。这里的“已有”指部署配置已准备好，不要求 Zadig 中已存在对应服务。

## 所需信息

项目展示名称、项目标识、项目类型，以及每个待创建服务的名称和 YAML、Helm Chart 或服务模板的来源。按实际需要补齐代码源、仓库、分支、文件分组或模板参数；创建环境时还需环境、集群等必要参数。

## 处理步骤

1. 查询当前用户可访问的已有代码源、配置和模板，将名称解析为内部标识，不要求用户知道 ID。
2. 项目默认私有，管理员为当前用户；确认项目名称、标识和 K8s YAML 或 Helm 类型。
3. 使用已有 YAML、Chart 或服务模板，不 clone 仓库，不写仓库，不从源码生成服务配置或构建脚本。
4. 每批最多二十个服务，明确来源和文件分组，不将每个 YAML 自动拆成一个服务，不覆盖同名资源。
5. 构建只使用已有构建模板，无合适模板则明确跳过。项目初始化默认包含创建工作流，复用 AutoCreateWorkflow，不按有无构建另改规则，不执行工作流。仅用户明确拒绝创建工作流时传 `create_workflow=false`。
6. 生成确认清单前，主动询问选择：不创建环境、只创建环境不部署服务、创建环境并部署指定服务。创建环境时补齐环境名称、集群、Kubernetes namespace 和镜像仓库，提交 `environment`；只创建环境时 `environment.services=[]`，部署时仅填用户选定的服务。仅用户明确选择不创建环境时传 `skip_environment=true`，不能将“不部署服务”理解成跳过环境，也不能自动选择全部服务。已保存的选择不重复询问。用户选择系统默认镜像仓库时，查询 `registries` 完整候选并按 `is_default=true` 选择，不将“默认”当作仓库名称搜索；新项目尚未创建时不传该项目的 `project_key`。查询失败应如实说明，不通过更换无关关键词反复重试。
7. 调用项目初始化工具生成清单。创建环境可能部署资源，必须列入确认范围，经卡片确认后由程序执行。

## 补问方式

模板优先使用用户给出的完整名称，不要求用户填写 ID。YAML 和构建模板通过 `query_catalog.keyword` 传入完整名称，未匹配时按返回的 `next_page` 继续读取后续页；找到精确匹配后查询详情。名称不明确或有歧义时补问，不擅自用相似名称替代。其他资源沿用原接口的名称查询能力，不因第一页没有匹配就认定资源不存在。

翻完模板分页仍无精确匹配时，立即说明未匹配到用户给出的名称并补问完整名称或配置来源，不把模板名称猜作分支、目录或构建模板继续探索。只列出已经查到的候选，不编造候选。询问服务配置来源时说明可选择代码仓库或已有服务模板，按选择收集参数，不统一要求仓库路径。

按工具返回的缺失字段补问，优先使用已有候选，不反复询问已保存的参数。继续原任务时先恢复参数草稿，再合并用户修改。

用户明确要求三个等数量时，首次调用也必须记录 `expected_service_count`，即使尚未知道服务名称；缺参时仍调用初始化工具保存草稿，不编造服务占位。先确认总数及名称，再询问是否共用代码源、仓库和分支，共享信息只问一次，按服务填入；分别补齐各自路径、模板和变量。

继续同一任务时沿用原 `skill_execution_id`，后端自动恢复和合并已保存草稿；可以只提交本轮修改字段及对应服务名，不要求重新发送完整列表。省略或传空服务列表不删除已有服务，明确移除才传 `remove_services`；替换名称须明确移除旧名并新增新名。总数改变时明确更新 `expected_service_count`，不能通过漏传服务缩小范围。布尔开关需明确传 false 才关闭，清空可选配置使用 null。

模板缺少参数时按服务汇总工具返回的缺项，已补齐的值不再询问；更换模板后重新核对该服务的变量，不影响其他服务。凭据或 YAML 类型参数须在原模板中预配置，不能让用户在聊天中填写。

## 输出要求

按本轮指定的系统语言展示项目、服务、来源及将执行的动作，说明构建等可选步骤的跳过原因；清楚提示待补问、待确认和逐项执行结果，不索要或展示明文密钥。

## 完成条件

本次确认范围内的必要步骤全部完成，可选步骤按规则跳过，才可报告初始化完成；缺失字段、待确认清单、失败或待核实结果均不算完成。
