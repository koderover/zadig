# 效能诊断

## 适用场景

用户要求分析明确指定项目的构建、测试、部署、发布质量和效率，找出瓶颈并给出优化建议。

## 所需信息

一个或多个明确的项目名称或标识，以及分析时间范围。默认最近三十天，每次最多十个项目、九十天；没有项目时必须补问，不扫描全部项目。

## 处理步骤

1. 调用效能诊断工具，按系统级效能洞察权限查询，不要求逐项目查看权限。
2. 显式传入项目列表和起止时间，复用原效能分析接口及原模型返回的报告，不另外生成统计算法。
3. 项目名称存在多个匹配时，展示原接口返回的候选标识并让用户选择，不扩大到全部项目。
4. 根据原报告解释瓶颈、关键指标和可操作建议，区分事实、原报告结论和进一步推断。
5. 同次运行不要重复请求相同报告，超时、失败或无有效报告时如实说明，不自动重试。

## 补问方式

参数不全也先调用本 Skill 的业务工具，按返回的 `missing_fields` 补问。继续同一任务时沿用 `skill_execution_id`，只传本轮补充或修改的字段；后端恢复原参数，不用新页面覆盖原目标。

项目缺失或名称有歧义时补问；超出项目数量、时间范围或仅提供一侧时间时，请用户给出完整且有界的范围。不以当前页面的项目替代用户未明确指定的分析对象。

## 输出要求

按本轮指定的系统语言说明指定项目、起止时间、报告来源、质量和效率结论及改进建议。只使用原报告正文，不展示内部提示词、输入数据或凭据，不将估算 Token 当成实际消耗。

## 完成条件

成功取得有效原报告并完成回答才算完成。报告失败或为空时不报告诊断成功，不自动修改构建或工作流配置。
